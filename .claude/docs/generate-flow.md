# Generate-flow invariants (agent rules)

> The short rule set for `/api/generate/stream` and `lib/pipeline/` — read it before editing either. Each rule names the code that enforces it; that code, and its tests, are the detail.

`/api/generate/stream` spends real cUSD per run, so its body is **hostile**. Hard rules:

- **Verify on-chain before any paid work.** `verifyPayment` (`lib/agent/orchestrator.ts`) decodes `ThreadRequested` from `payTxHash` and asserts threadId/payer/token/mode + `amount == requiredAmount`; route rejects with **402 before opening the stream**. Never trust `amountPaidRaw` — persist the verified amount. That `requiredAmount` read is **pinned to the payment's own `blockNumber`**, never head: the price is settable, so reading at head would let one `setPrice` reject every in-flight thread — money taken, nothing delivered.
- **One generation per payment.** Up-front `threads` insert runs **before** the stream: unique-violation (`23505`) → **409**; any other insert error → **503** fail-closed; both zero spend. Supabase-down is a documented degraded mode, not a bug to "fix".
- **Settle gates delivery.** `step_output` is emitted **only after** the step's settle confirms — `groqStep`, `runModeB`, and `factCheckStep` (whose revision replaces the draft, so delivering it before its settle showed content the run had not paid for and revoked it on failure). Never move the emit before settle — it reintroduces free-content-plus-refund. Soft steps (Serper, FactCheck) still settle on Celo; on Base they skip `executeX402Call` (`settlesSoftStepsOnChain`) because Groq already settles via Model 2 and the Base hop is only ETH to a simulated sink. Do not skip the Groq settle, including the legacy fallback.
- **Every failure is clean and refundable.** `boundThread`-validated (empty/junk → throw *before* settle, no spend); receipt waits bounded (90s); a hung run hits the internal **150s deadline** → `fatal` → thread `failed` → refundable (not a platform SIGKILL stuck `pending`). *Pipeline aborts on deadline so no settle after fatal: `5603fe9`.*
- **The fact-check must match the draft tweet-for-tweet.** `factCheckStep` replaces the draft on 5 of the 6 modes, so its output is `boundThread`-validated *and* count-checked against the draft; a mismatch (a refusal collapsing to one tweet, a rambling answer inflating to dozens) is a soft-step failure that keeps the unchecked draft rather than delivering junk as `completed`.
- **Retry, then escape hatch. Auto-QUEUE a refund, never auto-SEND one.** Soft steps `retryOnce`, scoped to the external call only, never around settle. Still degraded → preview surfaces a one-tap `kind=partial` refund request; auto partial-refund was deliberately rejected, because a degraded thread is still a delivery and whether it was worth the price is the user's call. A run that delivered **nothing** is different: the nightly sweep (`lib/agent/reconcile.ts`) queues a `full` request for it without the user asking, since the alternative is a paid user who closes the app and is never refunded. Neither path sends money — a human still drains the queue.
- **The terminal write is the delivery record.** Both `completed`/`failed` updates retry; a `completed` write that never lands pages ops, because the row then claims a delivered thread was never delivered and `reconcile.ts` would sweep it into a refund.
- **Cost display.** `X402_SINK_ADDRESS` overrides the default `0x…dead` burn sink (unset = burn, demo). Displayed cost derives from `GROQ_COST_CUSD` (single source) and cannot drift from what settles.

Soft (🟢) vs hard (🔴) step semantics: `lib/pipeline/runModeB.ts` (soft steps catch and emit `step_failed`; the Groq step rethrows). Thread state machine: `pending` → `completed` | `failed`, written only by the route.
