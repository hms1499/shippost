# x402 — two settlement models (agent rules)

> Canonical walkthrough: [`docs/ARCHITECTURE.md` §2.3](../../docs/ARCHITECTURE.md) (table + diagram) and the history note there. This file is the short rule set; read §2.3 for the *why*.

The codebase has **two unrelated mechanisms** named "x402" that flow money in **opposite directions**. Do not conflate them.

- **Model 1 — in-process, on the user's payment chain (we BUY services).** Pipeline steps (`lib/pipeline/*Step.ts`) simulate x402 by pulling stablecoin from **AgentWallet** via `settleX402Call` → cap-enforced `executeX402Call`, on whichever supported chain the thread was paid on (Base or Celo) and in the token the user paid — that is what makes each thread self-funding out of its own 50% split. Since Model 2 went live this covers Serper/CoinGecko/FactCheck — and the **Groq fallback** when the x402 rail is down (`generateDraft` alerts ops and degrades here).
- **Model 2 — real x402 (live for every paid thread's Groq settle).** `generateDraft` routes the Groq spend through `payGroqViaX402` → `app/api/x402/groq/route.ts` (`withX402` + CDP facilitator): the agent EOA signs an EIP-3009 `X-Payment`, and USDC settles to `X402_PAY_TO` on the chain named by `X402_CHAIN_ID` — Base via the Coinbase CDP facilitator, or Celo via the hosted Celo facilitator (`X402_FACILITATOR_AUTH=api-key`, prepaid credits at $0.001/settlement). **The Celo facilitator serves x402 v1 only** while `@x402` 2.14 emits v2, so Celo chains route through `lib/x402/facilitator-v1.ts`, which translates the envelope at the facilitator boundary and nowhere else — never teach the rest of the codebase that v1 exists, and delete the shim once Celo serves the v2 kind it already advertises. Enabled by `X402_SETTLE_MODE=x402` + `X402_CHAIN_ID` (global — deliberately NOT keyed on the user's payment chain, which since 2026-08-14 can be Base or Celo). Verify-before-handler, settle-only-after-200. Proven on Base mainnet 2026-06-03.

**Rule (non-negotiable):** any public, agent-callable x402 surface MUST verify a signed `X-Payment` before any spend, and MUST never expose `settleX402Call` unguarded. This exists because the *original* `/api/x402/*` proxies were an unauthenticated AgentWallet drain (removed in `8f4c222`; safe reintroduction `c8a796b`). Detail: `docs/x402-explained.md`, `docs/x402-flow-diagrams.md`, `docs/x402-mainnet-proof.md`.
